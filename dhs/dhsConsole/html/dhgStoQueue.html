Queue Action

Queuing is defined to be the grouping together of files which will be written onto a single physical unit of media, whether the media be a CD-R, EXABYTE, DVD, Mammoth-tape or some other medium.

When a queuing action is processed an attempt is made to "queue" all of the files which have not been queued already that have been retrieved by the Storage Server. The Storage Server will use an external application for queuing specified in the Storage Server's configuration file dhsStorage.config. Typically, the application used is mediaQueue.

A name is assigned to each unit of media created by the queuing process. These units can be viewed in the unit window. This name is prefixed by some predetermined name and appended with a numerical value.

The algorithm used to select files attempts to minimize the number of directories that are split across units of media. This is particularily useful for user media. The algorithm also gives preference to files with earlier notification dates (older). However, if an older file does not fit onto a unit of media a newer file may be chosen. If two files have the same date then they are chosen lexicographically.

Viewing Queue Information

There are three status records associated with queuing. They are:
  • Queue Size.
    The number of media units (CDs) of data that can be queued. For example, a value of 2.32 indicates that there are 2 and 1/3 CD's of data waiting to be queued.
  • Queue State.
    Indicates the current state of the queue action, expected values are given below.
  • Prepare Number.
    The number of media units (CDs) that can be prepared, have been prepared. For example, a value of 3 indicates that there are 3 units of media queued waiting to be prepared.
All three status records are displayed on the Storage Server's window and on the Request window. The Request window displays each of the status records in a non-editable box. The subsystem window uses a combination of text and colours to portray this information.

Obtaining Further Queue Information

Further information, the list of files that may be queued, can be obtained by pressing the "queue" information button on the Storage Server window. This will display the Storage Server's Action Information window. Similarly, the list of media units that are ready for preparing (have been queued) can be obtained by pressing the "queue" information button.

Altering Queue Information
(Issueing commands)

The Queue information that is displayed can not be changed directly. However, it does change as the result of the following several operations:
  • Queuing of data,
  • Rollback(undo) Queuing of data,
  • Preparing of data,
  • Rollback Preparing of data,
  • refresh the Storage Server,
  • reset the Storage Server, and
  • initialize of the Storage Server.
.

Expected Queue State Values

 The expected queue state values are listed in the table below. Given any particular state there is one or more states the action can move to. The state transition diagram below depicts the allowed moves (transitions).

Expected Queue State Values
Value Interpretation
ROLLBACK REQUESTED The last queue action that was processed is currently waiting "undone"
ROLLBACK IN-PROGRESS The last queue action that was processed is currently being "undone"
IDLE No processing is currently being performed on the data to be queued.
REQUESTED The Storage Server intends to queue the files that are waiting to be queued.
IN-PROGRESS Data is currently being queued.
